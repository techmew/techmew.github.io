画像スリム 制作プロンプト

GT3専用のPNG軽量化ツールから、写真やブログ画像にも使える汎用版へ作り直すための完全プロンプトです。

実際のツールを開く
あなたはこのプロジェクトのフロントエンドエンジニア、画像処理ツール設計者、UI/UXデザイナー、QA担当を兼任してください。

目的は、ブラウザだけで画像の縮小・軽量化・形式変換を行える単一HTMLツール「画像スリム」を完成させることです。

企画説明やコード断片だけで終わらず、保存してブラウザで開けばそのまま動作する完成したHTML/CSS/JavaScriptを成果物として作ってください。

==================================================
1. 基本コンセプト
==================================================

専門知識がなくても、
「画像を入れる → 縮小方法を選ぶ → 保存形式を選ぶ → 処理する → 比較する → 保存する」
だけで使える画像ツールにする。

画像は外部サーバーへ送信しない。
ブラウザ内だけで処理する。
PCでもスマートフォンでも使えるレスポンシブUIにする。

対応入力：
・PNG
・JPEG / JPG
・WebP

最大100枚をまとめて読み込めるようにする。

==================================================
2. 縮小方法
==================================================

最低限、次の4モードを実装する。

A. パーセント縮小
・1〜100%
・75%
・50%
・25%
・10%
などのクイックボタン

B. 最大サイズ
・最大幅
・最大高さ
・縦横比を保って枠内へ収める
プリセット例：
1920×1080
1280×720
1024×1024
800×800
512×512
466×466
200×200

C. 指定サイズ
・幅
・高さ
・縦横比を保つON/OFF
・Contain
・Cover
・Stretch
を選べる

Coverでは中央クロップ。
Containでは画像全体を見切れさせない。
Stretchでは指定寸法へそのまま変形。

D. 目標容量
・KB / MB指定
・JPG / WebPでは品質を段階的に調整
・品質だけでは入らない場合、ユーザーが許可していれば寸法も少しずつ縮小
・PNGでは容量調整に限界があることを説明
・結果が目標容量を超えた場合でも最小候補を返し、失敗理由を表示できる構造

==================================================
3. 保存形式
==================================================

出力：
・元形式をできるだけ維持
・PNG
・JPG
・WebP

JPG/WebP：
・高画質
・標準
・軽量
・かなり軽量
などの品質プリセット

JPGへ変換する場合、透明部分を塗る背景色を指定可能にする。
初期値は白。

PNGは透過を維持する。
完全透明画素のRGBを0へ整理し、不要データを減らすオプションを用意する。

==================================================
4. アップスケール防止
==================================================

「元画像より大きくしない」を初期ONにする。

小さい画像を誤って1920×1080などへ引き伸ばさない。
ユーザーがOFFにした場合のみ拡大を許可する。

==================================================
5. 一括処理
==================================================

最大100枚。

読み込んだ各画像について：
・ファイル名
・元容量
・元寸法
・処理後容量
・処理後寸法
・削減率
・処理済み状態
を表示する。

画像サムネイルを一覧表示。
クリックすると元画像と処理後画像を大きく比較できる。

一括処理中は：
・進捗バー
・処理数
・ボタン無効化
を行う。

1枚で失敗しても他の画像の処理を止めない。

==================================================
6. プレビュー
==================================================

元画像と処理後を左右に並べて比較。

表示：
・寸法
・容量
・形式
・何%軽くなったか

透明画像が見やすいチェッカーボード背景を使う。

スマホ幅では上下に並べる。

==================================================
7. 保存
==================================================

各画像に「保存」ボタン。
全処理済み画像に「全部保存」ボタン。

出力ファイル名：
元ファイル名 + "_slim" + 拡張子

例：
photo.jpg
→ photo_slim.webp

ブラウザの複数ダウンロード許可が必要な場合があることを説明する。

==================================================
8. UI
==================================================

明るく、親しみやすく、迷わないデザイン。

色：
・白
・ピンク
・紫
・水色
・ミント
を中心としたポップな配色。

暗い専門ツール風にしない。

画面構成：
左または上：設定
右または下：比較プレビュー

設定順：
1. 画像を選ぶ
2. どう縮小するか
3. 保存形式
4. 処理
5. 結果確認
6. 保存

技術用語だけを並べず、日本語で意味を説明する。

==================================================
9. プライバシー
==================================================

画面上に
「画像は外部へ送信せず、このブラウザ内で処理します」
と明記する。

外部APIへ画像を送らない。
サーバーアップロードを要求しない。

==================================================
10. エラー処理
==================================================

次を分かりやすく処理する。

・未対応形式
・100枚超過
・画像デコード失敗
・Canvas生成失敗
・toBlob失敗
・巨大画像でメモリ不足
・幅、高さ、％が不正
・容量指定が不正
・保存形式非対応
・処理後データ生成失敗

エラー時に画面全体を止めない。

==================================================
11. 元ツールから引き継ぐ強み
==================================================

元になった「GT3 PNG 極限軽量化ツール 50枚対応」の長所を残す。

・複数枚一括
・元画像／処理後比較
・サムネイル一覧
・目標容量
・透過PNG
・軽量化後の寸法・容量表示
・ブラウザ内処理
・1枚ずつ保存
・まとめて保存

ただしGT3専用の文言や20KB固定思想は外し、一般画像向けに拡張する。

スマートウォッチ用途は便利なプリセットの一つとして残す。

==================================================
12. 完成条件
==================================================

以下をすべて満たすこと。

・単体HTMLで動く
・PNG/JPG/WebPを読み込める
・最大100枚
・％縮小
・最大サイズ
・指定サイズ
・目標容量
・形式変換
・透過PNG
・JPG背景色
・アップスケール防止
・処理前後比較
・削減率表示
・1枚保存
・全部保存
・レスポンシブ
・ブラウザ内処理
・分かりやすい日本語UI
・主要処理でエラーが出ても他画像処理を継続

説明だけで終了せず、実際に動くHTMLファイルを作成し、ブラウザで基本動作確認まで行ってください。
