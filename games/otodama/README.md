# OTODAMA∞ — v0.9.5 (2026-10-26)

**Game:** https://techmew.github.io/games/otodama/

声の特徴（音量・音程・響き・リズム・安定・息）からキャラクターを生成するブラウザゲーム。マイクがなくても試用キャラで遊べる。声の録音は本人が許可した場合のみ行う。

## v0.9.5 新規改善（04:00 JST）

- **オンライン再接続（試作）**：対戦中の通信断を15秒猶予に変更。128bitの短期復帰トークンを検証し、同じ席・HP・共鳴を復元。サーバーが攻撃予兆から再同期。クライアントは最大4回自動再接続。第三者の無効トークンを拒否。本番未検証。
- **リアルタイム演出同期**：900msのサーバー予兆とガード/回避UIを一致。命中アニメーションをサーバー判定到着時に表示し、古いターンの操作応答を無視。
- **勝利で進む冒険**：勝利でのみステージ進行。敗北時は同じステージで別の新しい敵と戦う。挑戦回数をローカル保存/バックアップに追加。
- **逆転共鳴**：COM戦でHP35%未満のジャストガード成功時、1試合に1回だけ共鳴+25。
- **BGM深化**：6環境の独立メロディと小節単位のフレーズ変化。BGM音量をブラウザ保存。
- **テスト**：Nodeの復帰トークン/切断猶予/不戦勝、Chromiumの復帰/HP同期/次戦/保存/横画面を検証。Cloudflare公開・外部2端末・Android実機は未検証。

## v0.9.4 新規改善（03:00 JST）

- **サーバー裁定オンライン対戦（未デプロイ）**：WebSocket接続後、Durable Objects が900msの攻撃予兆・ダメージ・HP・ガード/回避成功・必殺技消費・勝敗を裁定。両端末へ同じ戦闘状態を配信し、各プレイヤーがリアルタイムにガード/回避/必殺技/戦術を操作できる。従来の事前計算再生に代わる新プロトコル `live_start/live_turn/live_ack/live_impact/live_end`。旧 `battle` のクライアント再生処理は互換用に残す。
- **通信遅延対策（試作）**：サーバー発行nonceへのpongからRTTを計測し、サーバー時刻で判定するガード/回避窓を最大90ms補正。クライアント申告の攻撃力・時刻は採用しない。回線品質による不公平を完全には解消しない。
- **離脱・連戦**：v0.9.4時点では切断時に残存プレイヤーの不戦勝（v0.9.5で15秒猶予へ変更）、試合中の二重開始を禁止。オンライン結果から「次の対戦相手を探す」へ移動。
- **ステージ地形の攻略**：6種類の環境に対応した周期的な地形効果（上昇気流・雷撃・水圧・溶岩・星屑・氷結）をダメージ/共鳴/回復に反映。6章の冒険テキストを追加。
- **進行バックアップ**：ゲーム画面からJSONを書き出し・読み込み。形式と数値を検証し、異常ファイルは拒否。録音した音声そのものはバックアップに含めない。
- **品質検証**：サーバー仮想2ソケット・サーバー時計・遅延補正・切断・レート制限、ChromiumでオンラインUI/COM連戦/保存のテストを追加。


## v0.9.3 から引き継いだ機能

- **6種類のステージ環境**：蒼天回廊／雷霆都市／深海遺跡／紅蓮火口／星屑庭園／氷晶要塞。背景をCanvasで描画し、ステージごとに色・構造物・音楽のテンポ・音階が変化。
- **ボス固有の3連携**：5ステージごとに「メテオ・ブレイク」「共鳴レーザー」「衝撃障壁」。攻撃予兆をHUDに表示。HP45%以下で攻撃強化。
- **BOSS BREAK**：ジャストガード35%、回避25%、必殺技30%を蓄積。100%でボスの攻撃1回を無効化。ガードの上手さが攻略につながる。
- **次戦限定の3択強化**：戦闘結果で「攻撃+15%」「最大HP+30」「初期共鳴+34」を選択。次のCOM戦だけ有効、選択しなくても進める。ボス撃破XP追加（通常+2／10ステージごとの伝説+4）。
- **サウンド改善**：攻撃予兆音と命中音を分離、ボス戦はテンポ・メロディを変化。録音声再生・音量設定を維持。
- **省電力描画・横画面対応**：端末設定に応じた初期省電力、任意ON/OFF・保存、残像・背景エフェクトを削減。横画面ではアリーナと操作UIを2列に配置。
- **WebSocket入力の堅牢化**：JSONの `null`・配列などを安全に拒否。`cleanCreature` の配列入力も拒否。

## 現在遊べる内容（COM）

- **連続ステージ:** 結果画面から「次のバトルへ →」。敵の名前・外見・属性・能力がステージごとに変化。5戦ごとに強敵、10戦ごとに伝説の敵。敗北後は同じステージで別の挑戦者と戦う。進捗はブラウザ保存。
- **プレイヤーの判断:** 敵の攻撃タイミングに合わせたジャストガード、成功すると次の自分の攻撃にカウンター補正、連続成功で補正が上昇。敵の攻撃を早めに見切る回避（成功で被ダメージ0、3回の敵攻撃クールダウン）、声に応じた固有必殺技、攻め・バランス・守りの切り替え。キーボード Space/J/K/1/2/3 対応。
- **演出と音:** Web Audio合成の自作BGM、ステージ・HP危機でテンポ/旋律変化。BGMとSE音量を個別設定。録音済みの声を戦闘中に再生。敗者の爆散、勝者の名前と WIN❗️表示。
- **長期要素:** 経験値・レベル・連勝、種族図鑑、日替わりボス、属性相性。保存はローカルストレージ（ブラウザ削除で消える）。
- **キャラ生成:** 12種族・多部位の外見組み合わせ、名前3,355万通り以上。組み合わせ数は種類の乗算であり、必ず異なる見た目が出る保証ではない。

## オンラインの現状とプライバシー

- Cloudflare Workers + SQLite-backed Durable Objects の招待ルーム・ランダムマッチ用コードと模擬テストは用意済み。**Cloudflare公開・実際の2端末接続は未完了。**
- オンラインv0.9.5コードは**サーバー裁定のリアルタイム入力試作**。ガード・回避・必殺技・戦術がHPと勝敗に影響する。ただし本番Cloudflareデプロイと独立2端末での実通信は未検証。
- 自分の録音音声を対戦相手に送るかは**初期OFFのチェックボックスで明示的に選択**。相手音声のミュートも可能。サーバーは音声を永続保存しないが、送信先の端末での複製を防止できない。
- 240件の禁止表現とURL・連絡先の簡易検知、表記正規化をオンライン名・タイプに適用。サーバーで能力値を再計算し、未知の属性を置換、連続送信を制限。**録音音声の発話内容は自動審査されない**。フィルタの誤検出・検出漏れは残る。
- 声の特徴量自体はクライアント申告で検証できないため、競技ランクや賞金戦には利用しない。

## テスト

```sh
cd games/otodama
node --check worker.js
node test-ui-source.cjs
node test-matchmaker.cjs
node test-room.cjs
node test-moderation.mjs
```

上記は構文・静的・模擬通信テスト。別途、Chromiumのモバイルエミュレーションで連続バトルとUIを確認。オンラインUI/進行バックアップは `python test-live-browser.py`、`python test-save-browser.py`、`python test-reconnect-browser.py` で確認可能。Android実機マイク/BGM、Cloudflare本番、2端末オンラインの動作は未確認。

ブラウザの実動作テスト（Python Playwright と Chromium が別途必要）：`python test-gameplay-browser.py`。ローカルHTMLを `page.set_content` で読み込み、実ゲームの820msをテスト時のみ45msに短縮して連続戦を確認する。ブラウザ外部通信やCloudflare公開の成功を意味しない。

## デプロイ

`.github/workflows/deploy-otodama-worker.yml` はGitHub Actionsに配置する。GitHubリポジトリに `CLOUDFLARE_ACCOUNT_ID` と `CLOUDFLARE_API_TOKEN` をActions Secretsとして登録して手動実行。`DEPLOY_GUIDE.md` を参照。認証情報はコードに記録しない。デプロイ後のWorker URLを `DEFAULT_SERVER_URL` に設定すると一般ユーザーがURL入力不要になる。

## ファイル

- `index.html`：ゲームUI・描画・戦闘・Web Audio・ローカル保存
- `worker.js`：Cloudflare Worker + Durable Objects（Room/Matchmaker）
- `moderation.js`：オンライン公開テキストの禁止語・個人情報判定
- `wrangler.jsonc`：Worker設定
- `test-*.cjs`, `test-moderation.mjs`：模擬テスト
- `test-live-browser.py`, `test-save-browser.py`：ブラウザUI/保存のテスト
- `PROGRESS.md`：毎時開発ログ・次回引き継ぎ

開発範囲は `games/otodama/` と専用の `.github/workflows/deploy-otodama-worker.yml` のみ。既存の他ゲームやブログを変更しない。
