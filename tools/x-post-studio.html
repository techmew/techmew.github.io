X Post Studio

Xへ投稿する前の文章を、誤字脱字・読みやすさ・構成・絵文字・ハッシュタグ・コンプラまでまとめてAIで整えるスマホ向けツールです。

X Post Studioを開く

このツールで何ができる？

テキストボックスへ普段どおりに文章を書き、絵文字量と「通常投稿 / 長文」を選んでAI処理を実行します。元文章の口調はできるだけ残したまま、次の処理をまとめて行います。

  • 誤字脱字・明らかな誤変換の修正
  • 読みやすい文章への整理
  • 「自然」「反応重視」「短く強め」の3パターン生成
  • 絵文字を「多い / 中 / なし」で調整
  • 内容に関連するハッシュタグを0〜3個提案
  • 誹謗中傷、個人情報、危険な断定などのコンプラ注意
  • X通常投稿向けの文字数調整、または長文のまま整形

AIが「バズ」を保証するものではありません。リアルタイムのXトレンドを取得しているふりもせず、文章の冒頭、情報量、読みやすさ、関連タグなどを改善するための補助ツールとして動きます。

なぜ最初にCloudflareの設定が必要？

X Post Studioの画面自体はGitHub Pagesで動きますが、文章の校正や3案生成にはAIが必要です。そこで、各利用者が自分のCloudflare Workers AIを用意し、そのWorkerへ文章を送って処理します。

処理の流れ

X Post Studio → 自分のCloudflare Worker → Workers AI → 校正結果をX Post Studioへ返す

サイト運営者のAIキーを全員で共有する方式ではありません。自分のCloudflareアカウントを使うので、無料枠も利用者ごとに分かれます。

用意するもの

  • GitHubアカウント
  • Cloudflareアカウント（無料プランで可）
  • X Post Studio用のWorkerコードを置くGitHubリポジトリ

GitHub側では何を用意するのか

CloudflareへGitHubを接続するだけではAIは動きません。GitHub側に、Cloudflare Workerとして実行できる構成を用意する必要があります。X Post Studioでは、実際に次のファイルを作成して動かしています。

x-post-studio-ai/
├─ package.json
├─ wrangler.jsonc
├─ .gitignore
├─ README.md
└─ src/
   └─ index.js

package.json：Wranglerを使えるようにする

package.jsonでは、このプロジェクトがCloudflare Worker用であることと、Cloudflare公式CLIのWranglerを使うことを設定します。

{
  "name": "x-post-studio-ai-worker",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "wrangler dev",
    "deploy": "wrangler deploy",
    "check": "wrangler deploy --dry-run"
  },
  "devDependencies": {
    "wrangler": "^4.102.0"
  }
}

npx wrangler deployをCloudflareのDeploy commandに指定すると、このWranglerがWorkerをデプロイします。

wrangler.jsonc：Cloudflare Workerの設定本体

wrangler.jsoncでは、Worker名、実行するJavaScript、互換日、workers.devの利用、Workers AI Bindingを設定します。

{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "x-post-studio-ai",
  "main": "src/index.js",
  "compatibility_date": "2026-09-28",
  "workers_dev": true,
  "ai": {
    "binding": "AI"
  }
}

nameはCloudflare側で作るWorker名と合わせます。mainは実際に実行する src/index.js を指定します。workers_devを有効にすると workers.dev URLで公開できます。

ai.binding = AIがWorkers AIとの接続設定です。Workerコードでは env.AI としてAIを呼び出します。この設定がないと、X Post Studioから文章を送ってもAI処理できません。

src/index.js：文章を受け取ってAI処理するAPI

実際のAI処理は src/index.js に入っています。単にAIへ文章を投げているだけではなく、X Post Studioから安全に利用できるよう次の処理をまとめています。

  1. CORS処理：GitHub Pages上のX Post StudioからWorkerへPOSTできるようにする。
  2. GETによる稼働確認：Worker URLをブラウザで開いたときにサービスが生きているか確認できるようにする。
  3. ping処理：X Post Studioの「接続テスト」用。AI生成を実行せず接続だけ確認する。
  4. compose処理：元文章、絵文字設定、通常投稿 / 長文設定を受け取る。
  5. 入力チェック：空文字や25,000文字を超える入力を弾く。
  6. 通常投稿の文字数制御：通常投稿では280文字以内を意識し、余裕を持って短くするようAIへ指示する。
  7. 長文モード：長文は勝手にスレッド分割せず、そのまま読みやすく整える。
  8. 絵文字量の制御：「多い / 中 / なし」をAIプロンプトへ反映する。
  9. 元の口調を維持：元文の語尾や温度感を拾い、勝手に別人格の文章へ変えないよう指示する。
  10. 誤字脱字修正：明らかな誤変換、不自然な助詞、誤字を修正する。
  11. 3パターン生成：「自然」「反応重視」「短く強め」の3種類をJSONで返す。
  12. ハッシュタグ提案：文章内容に関連するタグだけを0〜3個提案する。リアルタイムトレンドを取得したふりはしない。
  13. コンプラチェック：誹謗中傷、差別、個人情報、違法・危険行為、医療・金融の強い断定、著作権侵害を助長する表現などを注意候補として返す。
  14. JSON解析：AIの返答をX Post Studioが扱えるJSONへ変換する。
  15. 出力の正規化：修正点、コンプラ警告、3つの投稿案、ハッシュタグ、各案の特徴という固定形式へ揃える。

使用しているAIモデルは @cf/google/gemma-4-26b-a4b-it です。現在は安定性を優先した2段階処理です。生成方針は原文維持を最優先にし、原文の90%以上を残す意識で、誤字・助詞・明らかな不自然さ以外は極力書き換えません。最初の前処理1回で安全チェックと日本語校正をまとめて行い、地名・店名・支店名・施設名のIME誤変換も確認します。たとえば『○○店』の直前が不自然な一般語になっている場合は、同音・近音の支店名への誤変換を疑います。確認済みの誤変換についてはコード側の確定補正も使い、例として『トライアル可能店』は『トライアル加納店』へ補正します。その校正文を2回目のAI処理で3案へ展開します。通常のAI呼び出し回数を3回から2回へ減らし、一時的なAI失敗時も前処理では安全なフォールバックを使って全体停止を減らしています。さらに最終出力では、原文の改行・段落区切りは維持しつつ、3行以上の過剰な空行だけを2改行へ圧縮します。全文を勝手に1段落へ結合する出力は不合格として再生成します。さらに生成後、入力にない年・日付が勝手に追加されていないかWorker側で検査します。たとえば元文に年がないのに「2024年」「2026年」などを追加した案は不採用にし、自動再生成します。一般的な数字まで一律に禁止する処理ではありません。たとえば助詞の「の」が「ノ」になった誤入力や、「で」が「出」になった音声入力・IME由来の誤変換も校正対象です。その後、Function Callingで3案・コンプラ・ハッシュタグを型付きで返すため、文章生成と誤字判定を一度に行う方式より安定します。

.gitignore：不要なファイルをGitHubへ上げない

node_modules/、Wranglerのローカル作業ファイル、開発用変数ファイルなどをGitHubへコミットしないよう設定します。

README.md：Cloudflare側の設定値を記録する

READMEには、Cloudflareで指定するProduction branch、Build command、Deploy command、Root directory、Workers AI Binding、Worker URLをX Post Studioへ登録する流れを残しておきます。後から設定を忘れてもGitHubを見るだけで復元できます。

このGitHub作業はChatGPTに任せると早い

GitHubをChatGPTと連携している場合、上記のファイル作成・コード実装・設定修正はChatGPTへまとめて任せられます。

たとえば「X Post Studio用のCloudflare WorkerをこのGitHubリポジトリに作って。package.json、wrangler.jsonc、src/index.js、README、.gitignoreまで全部用意して」と依頼すれば、GitHubへ直接ファイルを追加できます。

ChatGPTに任せられる作業

  • GitHubリポジトリ内の現在の構成確認
  • Worker用フォルダまたは専用リポジトリ向けファイルの作成
  • package.jsonの作成
  • wrangler.jsoncの作成・修正
  • Workers AI Bindingの設定
  • src/index.jsのAI API実装
  • CORS、接続テスト、入力チェック、JSON整形の実装
  • READMEとセットアップ手順の作成
  • Cloudflareのビルドエラーを見てGitHub側の原因を修正
  • Worker名、Root directory、デプロイ構成の整合確認
  • 既存サイトへ組み込む場合のフォルダ分離

実際にこのサイトでも、最初はGitHub Pagesのサイト本体をそのままCloudflareへ接続したため、リポジトリの取得と依存関係インストールまでは成功したものの、Worker用の package.json と wrangler.jsonc がルートに存在せず、npx wrangler deploy の段階で失敗しました。

そこでGitHub側に /workers/x-post-studio-ai/ を追加し、その中へWorker用ファイル一式を作成。Cloudflare側ではRoot directoryをそのフォルダへ変更する構成に修正しました。

このような「Cloudflareのビルドログを見る → GitHub構成の不足を特定する → 必要なファイルを作る → Wrangler設定を合わせる」という作業は、GitHub連携済みのChatGPTへ任せるとかなり省力化できます。

ただしCloudflare側で本人が行う操作もある

GitHubのコード作成はChatGPTへ任せられますが、外部サービスの認証や権限許可は利用者自身で行います。

  • Cloudflareへのログイン
  • Connect GitHubを押す
  • GitHub Appのアクセス許可
  • Cloudflareへ接続するリポジトリの選択
  • Build設定の保存
  • 必要に応じた「ビルドを再試行」
  • 発行されたworkers.dev URLの確認

ChatGPTを使わず手動で用意する場合

手動で作る場合は、公開しているWorkerテンプレートを自分のGitHubリポジトリへコピーします。

X Post Studio AI WorkerテンプレートをGitHubで見る

テンプレートには package.json、wrangler.jsonc、src/index.js、.gitignore が入っています。専用リポジトリのルートへそのまま配置してください。

CloudflareへGitHubリポジトリを接続する

1. Cloudflare Dashboardへログイン

Cloudflare Dashboardを開きます。アカウントを持っていない場合は無料アカウントを作成します。

2. Workers & Pagesを開く

Dashboardで「Workers」を開きます。画面によっては左メニューの「コンピュート」→「Workers & Pages」から入ります。

3. 「アプリケーションを作成する」を押す

Workers & Pages画面にある「アプリケーションを作成する」を押します。

4. 「Connect GitHub」を選ぶ

新規作成画面にGitHub、GitLab、Hello World、テンプレートなどが表示されたら、「Connect GitHub」を選びます。

5. CloudflareからGitHubへのアクセスを許可する

初回だけGitHub側の認証画面が開きます。CloudflareからGitHubリポジトリへアクセスするための許可を行います。すべてのリポジトリを許可する必要はなく、X Post Studio用に作ったリポジトリだけを許可しても構いません。

6. X Post Studio用のリポジトリを選ぶ

Cloudflareへ戻ったら、先ほど用意した x-post-studio-ai などのWorker専用リポジトリを選択します。

7. Worker名を確認する

テンプレートの wrangler.jsonc ではWorker名を x-post-studio-ai にしています。Cloudflare側のWorker名も同じ x-post-studio-ai にすると設定が分かりやすくなります。

Cloudflare Workers Buildsでは、Dashboard上のWorker名と、指定したRoot directory内にあるWrangler設定の name が一致している必要があります。一致しない場合はビルドエラーになります。

8. Build設定を入力する

専用リポジトリのルートへテンプレートを配置した場合は、次の設定にします。

Production branch：main

Build command：空欄

Deploy command：npx wrangler deploy

Root directory：/

Build commandは事前コンパイルが不要なので空欄です。Deploy commandはWranglerでWorkerをCloudflareへデプロイするためのコマンドです。

9. 「Save and Deploy」を押す

設定を確認したら「Save and Deploy」を押します。CloudflareがGitHubからコードを取得し、Workerをビルドしてデプロイします。

10. Workers AI Bindingを確認する

配布テンプレートの wrangler.jsonc には、Workers AI Bindingを最初から設定しています。

"ai": {
  "binding": "AI"
}

この設定により、Workerコードから env.AI を使ってWorkers AIを呼び出せます。

11. workers.devのURLを有効化する

デプロイが成功しても、workers.dev の公開URLが無効のままだとX Post Studioから接続できません。Worker画面の上部にある「ドメイン」タブを開きます。

「Worker URL」欄に、次のような2つの行が表示されます。

  • プロダクション：worker-name.account-subdomain.workers.dev
  • プレビュー：*-worker-name.account-subdomain.workers.dev

通常利用で必要なのはプロダクションだけです。プロダクション行の一番右にあるトグルスイッチをONにします。

ONにする：プロダクション

OFFのままでよい：プレビュー

触らなくてよい：「ドメインを追加」「ルートを追加」

トグルをONにすると、https://worker-name.account-subdomain.workers.dev のような公開URLが使えるようになります。

12. Worker URLをブラウザで直接確認する

有効化したプロダクションURLをコピーして、まずブラウザで直接開きます。

Workerが正常に動いていれば、JSON形式で "ok": true や "service": "X Post Studio AI Worker" といった内容が表示されます。

何も表示されない、404になる、Cloudflareのエラー画面が出る場合は、まだ公開URLかデプロイ設定に問題があります。X Post Studioへ登録する前にここを直します。

13. X Post StudioへURLを登録する

X Post Studioを開き、「AI接続」→「設定」へ進みます。Cloudflareで発行されたWorker URLを、https:// から始まる完全なURLで貼り付けて保存します。例：https://x-post-studio-ai.example.workers.dev。

14. 「接続テスト」を実行する

「接続テスト」を押し、接続成功と表示されれば初期設定は完了です。以後は文章を入力して「AIで3案つくる」を押せば、自分のWorkers AIで文章処理できます。

既存サイトと同じGitHubリポジトリへWorkerを置く場合

専用リポジトリを増やしたくない場合は、既存のGitHubリポジトリ内へ /workers/x-post-studio-ai/ のような専用フォルダを作る方法もあります。

この場合だけCloudflareのRoot directoryを、Wrangler設定があるフォルダへ変更します。

例：/workers/x-post-studio-ai/

Root directoryを / のままにすると、サイト本体など別のプロジェクトをWorkerとしてデプロイしようとして失敗する場合があります。Cloudflareはモノレポ構成で、各WorkerのWrangler設定があるフォルダをRoot directoryとして指定する方式に対応しています。

ビルドに失敗したとき

CloudflareのWorker画面から「デプロイ」→ビルド履歴を開くと、どの工程で失敗したか確認できます。

  • Missing entry-point：Root directoryまたはWrangler設定を確認
  • Worker nameが一致しない：Cloudflare側のWorker名と wrangler.jsonc の name を合わせる
  • GitHubを取得できない：CloudflareのGitHub連携権限を確認

設定を変更した後は、Build設定を保存して「ビルドを再試行」します。再試行時には保存済みの最新Build設定が使われます。

無料枠について

Cloudflare Workers AIのFreeプランには、1日10,000 Neuronsの無料割当があります。上限はCloudflareアカウント単位なので、この方式では利用者それぞれが自分の無料枠を使います。

Xへの投稿とアカウント切替

X Post StudioはXのパスワードや投稿用APIトークンを保存しません。X APIの有料投稿機能も使いません。

生成した文章をコピーし、Xの投稿画面を開く方式です。複数アカウントを使う場合は、アカウントごとにブラウザやブラウザプロファイルを分けてログインしておく運用を想定しています。スマホで特定ブラウザへ完全自動で振り分ける部分は、OSやブラウザによって制限があります。

プライバシーと注意点

入力した文章は、設定した自分のCloudflare Workerへ送信され、Workers AIで処理されます。X Post Studio側にはCloudflareのAPIキーを直接保存しません。

AIによる誤字修正・コンプラ判定・ハッシュタグ提案は補助機能です。法的判断や事実確認を保証するものではないため、投稿前に最終確認してください。
