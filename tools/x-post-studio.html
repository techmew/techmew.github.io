X Post Studio

スマホで文章を入力し、元の口調を残したまま、誤字脱字・構成3案・コンプラ・絵文字・関連ハッシュタグをAIでまとめて処理するX投稿サポートツールです。

X Post Studioを開く

できること

元文章の口調をAIが読み取り、別人格に変えずに校正します。誤字脱字・明らかな誤変換の修正、自然 / 反応重視 / 短く強めの3案、絵文字「多い / 中 / なし」、通常投稿 / 長文、関連ハッシュタグ、コンプラ注意をまとめて処理します。

長文は勝手に分割しません。複数のXアカウント名と、各アカウントで使うブラウザ名をスマホ内に保存できます。

利用者ごとにAIを分ける

共通のAIキーを全員で使う仕組みにはしていません。各利用者が自分のCloudflareアカウントでWorkerを作成し、そのWorker URLを自分のX Post Studioへ登録します。AIの無料枠も利用者ごとに分かれます。

Cloudflare Workers AIの無料セットアップ

X Post StudioのAI機能は、利用者それぞれが自分のGitHubと自分のCloudflareを接続して使う設計です。ここではCloudflareの現在の画面に沿って、GitHub接続からWorkerを公開するまでを順番に説明します。

1. Cloudflare Dashboardを開く

Cloudflare Dashboardへログインします。Cloudflareアカウントを持っていない場合は、先に無料アカウントを作成します。

2. Workersを開く

Cloudflare Dashboardのホーム画面から「Workers」を開きます。見つからない場合は、左メニューの「コンピュート」→「Workers & Pages」と進みます。

3. Workers & Pagesで「アプリケーションを作成する」を押す

Workers & Pages画面を開いたら、「アプリケーションを作成する」を押します。Cloudflareの新規作成画面が開きます。

4. 「Connect GitHub」を選ぶ

新規作成画面に「Connect GitHub」、GitLab、Hello World、テンプレートなどの選択肢が表示されます。X Post Studioでは「Connect GitHub」を選びます。

これは、利用者ごとに自分のGitHubリポジトリをCloudflareへ接続し、そのリポジトリからWorkerを自動ビルド・デプロイするためです。Cloudflare公式でも、新しいWorkerをGitHubへ接続する場合は、Workers & Pagesからアプリケーション作成へ進み、Gitアカウントとリポジトリを選択する流れになっています。

5. 初回だけGitHub連携を許可する

CloudflareとGitHubを初めて接続する場合は、GitHub側の認証画面が開きます。表示されたCloudflare Workers and PagesのGitHub Appを許可します。

GitHub側で「すべてのリポジトリ」または「選択したリポジトリのみ」を選べる場合は、X Post Studio用に使うリポジトリだけを許可しても構いません。

6. 自分のGitHubアカウントを選ぶ

Cloudflareへ戻ると、接続したGitHubアカウントまたはOrganizationが表示されます。自分がX Post Studio用に使うGitHubアカウントを選びます。

7. X Post Studio用のリポジトリを選ぶ

GitHubのリポジトリ一覧から、X Post StudioのWorkerコードを置いたリポジトリを選びます。今後は、利用者が自分のGitHubへコピーして使えるWorker用テンプレートリポジトリを用意する想定です。

まだ自分のリポジトリを作っていない場合は、この時点で先にGitHub側にWorker用リポジトリを用意する必要があります。X Post Studio本体とAI Workerは分けておく方が管理しやすいです。

8. Cloudflare側でプロジェクト設定を確認する

リポジトリを選択すると、Cloudflareのプロジェクト設定画面へ進みます。ここではプロジェクト名、Production branch、ビルド設定などを確認します。

Worker用リポジトリを専用テンプレートとして用意した場合は、基本設定をそのまま使える形にします。設定内容は実際のテンプレートリポジトリ完成後、この手順に固定値を追記します。

9. 「Save and Deploy」または「Deploy」を押す

設定を確認したら「Save and Deploy」または「Deploy」を押します。CloudflareがGitHubリポジトリを読み込み、Workerのビルドとデプロイを開始します。

10. Workers AI Bindingを追加する

Workerが作成されたら、そのWorkerを開き、Settings → Bindingsへ進みます。Workers AIのBindingを追加し、Binding名を必ず AI にします。

X Post Studio用Workerは env.AI を使ってAIを呼び出すため、Binding名が別の名前だと動きません。Cloudflare公式でもWorkers AIをWorkerから利用するにはWorkers AI Bindingが必要です。

11. workers.devのURLを確認する

デプロイが成功すると、Workerには https://xxxxx.workers.dev のようなURLが発行されます。このURLをコピーします。

12. X Post StudioへWorker URLを登録する

X Post Studioを開き、「AI接続」→「設定」を開きます。先ほどコピーした workers.dev のURLを貼り付けて保存します。

13. 「接続テスト」を押す

最後に「接続テスト」を押します。接続成功と表示されれば、誤字脱字チェック、文章構成3案、絵文字調整、関連ハッシュタグ、コンプラチェックをAIで処理できる状態です。

無料枠について

Cloudflare Workers AIのFreeプランには1日10,000 Neuronsの無料割当があります。利用者ごとに自分のCloudflareアカウントを使うため、あなたのCloudflare無料枠を他の利用者と共有する設計ではありません。

Cloudflare公式：Git連携でWorkerを作成 / Workers AI Binding公式手順 / Workers AI料金・無料枠

自分のGitHubで使いたい場合

この公開ページを共用する必要はありません。自分のGitHub PagesへHTMLをコピーし、自分のCloudflare Worker URLを登録して使う構成にできます。Worker URLはブラウザのlocalStorageへ保存するため、GitHubのソースへAIキーを書き込む必要はありません。

アカウント切替の扱い

Xのパスワードや認証トークンは保存しません。アカウントボタンは「どのアカウントで投稿するか」と「どのブラウザを使うか」の目印です。投稿時は本文をコピーしてXの投稿画面を開きます。

ここは実機確認が必要

スマホからChrome / Edge / Firefoxなど特定のブラウザを強制して開く方法は、Android・iPhoneと各ブラウザの仕様で挙動が異なります。X APIの有料利用には切り替えず、無料の範囲で実機テストしながら詰めます。

「バズる」について

AIがバズを保証することはできません。X Post Studioでは、冒頭の伝わりやすさ、情報密度、読みやすい改行、余計な前置きの削減、内容に関連するハッシュタグの提案を行います。リアルタイムのXトレンドを取得しているふりはしません。

コンプラチェック

誹謗中傷、差別、個人情報、違法・危険行為、医療や金融に関する強い断定、著作権侵害を助長する表現、根拠のない断定などを注意候補として表示します。AI判定なので、法的判断を保証するものではありません。
