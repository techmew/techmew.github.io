GitHub Pages

HTMLだけで作ったツールをGitHub Pagesで無料公開する流れ

自作HTMLツールは、手元に置いているだけだと自分しか使えません。そこで、画像縮小ツールやスマートウォッチ制作ツールをGitHub Pagesで公開しました。実際にやった構成を、できるだけ簡単にまとめます。

必要なのはHTMLファイルだけでもいい

GitHub Pagesは、静的なHTML、CSS、JavaScriptを公開する用途と相性がいいです。サーバー側の処理が不要なツールなら、単体HTMLでもそのまま公開できます。

自分のサイトではどう置いているか

himanekoでは、サイトのトップや説明ページとは別に、実際に動くHTMLを /apps/ の下へ置いています。

apps/
  image-slimmer/
    index.html
  watch-motion-studio/
    index.html

こうしておくと、紹介記事とツール本体を分けられます。説明ページには使い方や注意点を書き、実際に使う人は「ツールを開く」ボタンから本体へ進めます。

単体HTMLが便利な理由

ビルド環境が不要で、ファイルをそのまま置いて公開できるのが利点です。特に画像処理や動画の簡単な加工なら、CanvasやJavaScriptだけで完結する場合があります。

一方で、ブラウザだけでできることには限界もあります。巨大ファイルを扱うとメモリを使いますし、サーバー側処理が必要な機能は別の仕組みが必要になります。

公開ページだけ作っても分かりにくい

最初は「ツールがあります」と書くだけの紹介ページにしがちですが、実際には、何ができるのか、どこを押せば使えるのか、画像は外部へ送られるのか、といった説明が必要です。

そのため、自分のサイトでは「実際のHTML本体」「説明ページ」「制作プロンプト」「更新履歴」を分ける形にしました。

AdSenseを考えるならツールだけより説明も必要

ツール本体だけだと、検索から来た人には使い方や用途が分かりにくいことがあります。実際に作って分かった点、失敗したこと、使い方、制限などを記事として残す方が、サイト全体としても価値が出ます。

まとめ

HTMLだけで作った小さなツールでも、GitHub Pagesなら公開できます。自分は、まず使える本体を置き、その周りに説明記事や制作記録を追加していく方法にしました。

今後もhimanekoでは、完成品だけではなく「なぜ作ったか」「どこで詰まったか」まで一緒に公開していく予定です。
